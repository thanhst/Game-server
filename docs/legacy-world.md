# Authoritative legacy world runtime

`LegacyWorld` owns one map/zone's player records, normal mobs, owned summons, learned skills, selected skills, cooldowns, effects, and clock. It retains `shared_ptr<const ContentSnapshot>` and resolves actual class-scoped SQL skill definitions. Player IDs, normal mob IDs, and summon-owner IDs are separate namespaces, as required by the old packet routes. Each world has one owner thread; packet callbacks must enqueue work to that thread.

Create a world with an imported content snapshot, a valid source map ID and explicit random callback. Add resolved actor state with `addActor()`, including class and learned template ID → point mappings; use `addMob()` for resolved map mob state. `selectSkill()` rejects unlearned IDs. `attackMob()`, `attackPlayer()` and `useNonFocus()` build snapshots from owned state, evaluate `CombatRules`, preflight recipes and capacity, then commit the result and immediate effects. Call `advance(nowMs)` and consume `takeEvents()` on the owner thread. Definitions never hold actor cooldowns.

PvP eligibility remains an explicit adapter input. `attackPlayer(..., pvpAllowed)` must receive the result of the source permission rules. Attacking another actor's summon requires `attackMob(..., true, summonOwnerTargetAllowed)`; the default refuses it, and attacking one's own summon is rejected. Do not equate a transport session ID with a persisted player ID.

The complete zone-mob snapshot and current human/mob HP total are generated by the world for spirit-bomb evaluation. Class-scoped level data is used directly, so shared shield ID 19 across classes cannot alias a player's selected skill. Partial/unknown mechanic requests return `Unsupported`; failed admission and unsupported recipes leave actor, target, cooldown, and scheduled-effect state unchanged. RNG callback state is external and may have advanced before a failure; callbacks must not mutate unrelated world state.

## Actual lifecycle implementation

Sleep, blindness, chocolate metadata, hold links, energy protection, charge/special clears, and recovery timeout are scheduled and expired. Reapplying the same effect kind to the same target replaces its timer. Player and mob target namespaces remain distinct even with equal numeric IDs. Target debuffs can outlive a disconnected caster; hold links and departing actors' own effects are cleaned up. Energy-protection expiry clears the protection flag; it never creates a demo-style shield pool.

Summoning creates the source mob template with exact level-based HP, initial `(owner.x, owner.y-40)` position, owner-linked ID, damage percentage and lifetime. The summon follows accepted movement and is removed on lifetime expiry or owner removal. Follow-up attack rules are ported from `mob/Mob.java:930`: the eight specified owner skills, source damage percentage/Pikkoro set bonus, normal mob and PvP branches, dummy/Hirudegarn exceptions, player damage-limit and protection checks. The caller's post-PvP-hit below-five-percent guard from `Zone.java:1255` is preserved. A summon follow-up has no invented range or independent cooldown gate.

Transform charge and delay are scheduled, but final stat recalculation requires `setStatResolver()`. The callback receives the actor with the requested monkey flag and must execute the full source stat pipeline from authoritative inputs. The runtime then performs the source 50% recovery on activation and resolves stats again at expiry. Without that resolver, transformation is atomically `Unsupported`; multiplying already-resolved final stats would not reproduce `Info.setInfo()`. Identity changes or callback failures reject/roll back the operation.

`registerEffectRule()` adds start/expiry behavior for a new recipe kind. `setRuleProfile()` can install a separate game profile. Custom callbacks operate on provided value state, must preserve identity, and must not perform outside writes; world rollback cannot undo external side effects.

## Source boundaries

Map categories are ported from `map/TMap.java:124`–`172`: barrack, Cold, Nappa, pet map 155, Future and Babidi. SQL contains no terrain collision grid or pixel dimensions. `move()` therefore requires a `setMovementRule()` callback backed by real terrain data. The core applies the source dead/blind/frozen/asleep/charging/stone/hold gate from `Player.java:2452`; the adapter must implement `Player.move()` terrain, flight mana, waypoints, packet movement accounting, achievements and companion movement. There is no fabricated map rectangle or replacement speed formula.

The scheduler uses explicit millisecond deadlines and stable token order. The old Java timers run in separate threads/periodic update loops, so their wall-clock jitter and coarse update alignment are not reproduced. Nominal rule durations and order are deterministic here; this is a conscious runtime timing boundary, not a measured live Java equivalence result.

`add_power_and_potential_input`, death, visual and other semantic events still require the host's source-faithful reward, persistence, quest, NPC-retaliation and client-packet adapters. Ordinary mob autonomous attack/respawn, all boss subclasses, full player permission rules, full `Info` stat calculation, and unported area skills remain explicit integration work. A working `LegacyWorld` is not evidence that those systems already exist.

`tests/LegacyWorldTests.cpp` replays real SQL Dragon/Demon/shield/summon data, verifies independent cooldowns, target ID namespaces, exact effect boundaries, summon follow-up damage, transactional unsupported transforms, and custom effect scheduling. Tests were written and statically inspected; no C++/Java build or execution was performed.
